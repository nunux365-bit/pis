## §2.1 — Determinism contract (generic — binding; full-precision **P** in the model)

**Server** maps persisted **``final_amount``** to **two fractional digits** after JSON parse (half-away-from-zero on ties). **You** output **exact arithmetic** **P** from the contract chain — **do not** apply decimal trimming, ceiling/floor to paisa, or spreadsheet two-decimal **display** formulas in ``calc_notes`` or in reasoning you emit.

| ID | Rule |
|----|------|
| **D-1** | **One scalar pipeline:** Let **P** = the row’s resolved total from **``line_subtotal = base + SC + …``** (carry **full precision** through intermediates). JSON **``final_amount``** **= P** as a JSON number (enough precision to represent **P**; **not** a second invented total). Set **``calc_notes_amount``** per **§2.2** (mirror of transcript only). |
| **D-2** | **Terminal ``calc_notes``:** After **``line_subtotal=…``**, close with **``final_amount=<P>``** where **``<P>``** is **numerically identical** to the **rightmost** total on the **``line_subtotal``** line. **Forbidden:** a closing **``final_amount``** clause showing a value ≠ **P** (e.g. **``line_subtotal``** sums to **105000** but **``final_amount=107142.86``**). **Forbidden:** naming or invoking spreadsheet functions whose purpose is to coerce **P** to two decimals inside the transcript. |
| **D-3** | **Transcript vs JSON (billing):** **``summary_rows[].final_amount``** must **equal** **P** (allow only trivial float representation noise). **Pass 3** only if you rewrite **``calc_notes``** and **``final_amount``** **together**; then refresh **``calc_notes_amount``** per **§2.2**. |
| **D-4** | **No second brain:** After **P** is written, Pass 4–5, validators, **``self_checks``** **confirm** or **``needs_human_review``** — they **never** replace JSON **``final_amount``** from a separate recomputation while leaving ``calc_notes`` unchanged. |
| **D-5** | **Phase B (``OHC_ADMIN_INVOICE_PCT``):** **``line_subtotal = sum_B × invoice_admin_pct ÷ 100``** at full precision; JSON **``final_amount``** = that value at full precision; set **``calc_notes_amount``** per **§2.2**; **server** alone maps **``final_amount``** to two fractional digits after parse. |

## §2.2 — ``calc_notes_amount`` (schema field; **mirror only**)

- For **every** row, **``calc_notes_amount``** must equal **only** the numeric literal in the **terminal** **`final_amount=…`** or **`final_amount: …`** clause inside that row’s **``calc_notes``** (same value you wrote in the transcript’s closing invoice line).
- **Single purpose:** copy that transcript figure into JSON for downstream readers. **Do not** treat **``calc_notes_amount``** as an independent billing input: **no** use in **``line_subtotal``** / **P** algebra, Phase B **sum_B**, **``totals.final_amount_total``**, caps, or **``self_checks``** — those use **``final_amount``**, **``line_subtotal``**, and **``calc_notes``** text per **§2.1** / **MATH-PRIMARY** only.
- Whenever you change **``calc_notes``**, set **``calc_notes_amount``** again from the **new** terminal **`final_amount`** clause (still **§2.2** only).

- **Step order:** In Pass 3, compute **intermediates in a fixed sequence**. Each later step uses **only** (a) raw inputs from Context / ``attendance_records`` / ``rate_lines``, or (b) **named values already computed in an earlier step** on that same row. **Do not** re-derive the same quantity from a coarser display formatting of an earlier value or by re-expanding an earlier formula.

## DEFINITIONS (use these names consistently in ``calc_notes`` class field)
**``MAP-STAFF-CAL`` — Monthly / high-frequency human staffing (calendar **T** only)**  
Matches **employee** lines that are **monthly** (or period lump) **human** staffing with absence proration and **no** low-frequency visit pattern — typical OHC doctor/nurse/paramedic seats.

A ``summary_rows`` line is classified as **``MAP-STAFF-CAL``** when **all** hold for its ``contract_rate_line_id``:
- ``billing_model`` = ``rate_attendance``
- ``billing_rules.pro_rata.method`` = ``working_days`` *(ingest label for LOP style — **not** permission to use Context ``working_days`` as **T**)*
- ``billing_rules.deduction.method`` = ``pro_rata_working_days``
- ``schedule_config`` has **no** ``visits_per_month`` and **no** ``visits_per_week`` (null/absent/empty). **``prescribed``** ``schedule_config`` with only **weekly ``slots``** (time-of-day bands on ``day_of_week``) **without** those visit counters **satisfies** this bullet — treat slots as **duty/coverage metadata** for a **monthly seat**, not as countable visit units unless **``C_VISIT_SESSION``** is triggered per its definition below.
- ``deduction.method`` is **not** ``per_shift_missed``
- The line is **not** already classified as **``C_VISIT_SESSION``** (visit/session billing — see **narrow** definition below)

**Denominator T (product; MAP-STAFF-CAL class):** **T = context ``calendar_days``** (N from Context). **Never** Context ``working_days`` for this class.

**Why calendar:** Human staffing billed **monthly** or at **≥5 days/week** (Mon–Fri-style) uses **calendar-month** proration so weekend-inclusive months match India MIS policy. Wording in ``billing_rule_text`` (e.g. “deduct by working days in the month”) is **commercial language**; it **must not** replace **T** with ``working_days``.

**Prorated base:** ``prorated_base = rate_amount × max(0, T − absent_days) ÷ T`` (``absent_days`` from ``attendance_records``).

**Service charge on the same row (apply after ``prorated_base`` is fixed):**
- **Lock ``prorated_base`` first** (Numeric chain discipline); SC always uses that **locked** value — **never** a parallel recomputation from ``rate_amount`` / ``T`` / ``A`` for the SC step.
- **``service_charge_type = percentage``:** SC = **locked** ``prorated_base × (service_charge_value ÷ 100)`` unless ``billing_rule_text`` / ``billing_rules`` explicitly define a different base for the percentage (then lock **that** base before SC).
- **``service_charge_type = fixed`` (default):** **SC = ``service_charge_value``** in full — **no** absence factor, **no** ``× (T − absent_days) ÷ T``, **no** inferring proration from base-fee wording alone.
- **``service_charge_type = fixed`` (proration — machine-readable + text):** Use **the same locked** **f** = ``max(0,T−absent_days)÷T`` as **``prorated_base``** when **either** (a) **``billing_rules.deduction.applies_to``** (JSON array) **includes the string** **``service_charge``**, **or** (b) **``billing_rule_text``** / **``deduction.formula``** **explicitly** states fixed SC is deducted or prorated **with** attendance (e.g. “fixed service charge deducted proportionally”). Then **SC = ``service_charge_value × f``** — lock **f** once; **never** a second **f** from a different **T**. **If** **``applies_to``** lists **only** **``base``** (no **``service_charge``**) **and** SC proration is **not** explicit in prose → **full** fixed SC.
- **Phrases that only describe the base fee** (e.g. “deduct absent days”, “working days in the month” for manpower) **do not** prorate fixed SC **unless** **``applies_to``** includes **``service_charge``** or SC proration is **explicit** in **``billing_rule_text``** / **``deduction.formula``**.

**Row total:** ``line_subtotal = locked_prorated_base + locked_SC`` (plus any other add-ons the same contract fields explicitly require), resolve **P**, then **``final_amount``** = **P** (see **MATH-PRIMARY** + **§2.1**; **``calc_notes_amount``** per **§2.2**; server maps **``final_amount``** to two fractional digits after parse).

**``calc_notes`` for ``MAP-STAFF-CAL``:** Must include the literal substring **India calendar-day manpower override** (downstream review uses it) and **``T=calendar_days (N)``** with **N** = Context value.

**Forbidden on ``MAP-STAFF-CAL``:** ``rate_amount × paid_days ÷ T``, ``rate_amount × present_days ÷ T``, or mixing paid-day accrual with absent-proration on the **same** row.

**``C_VISIT_SESSION``** — Visit or scheduled-session billing where JSON defines **countable billable units in the billing period** (e.g. **non-null ``visits_per_month``**, **``visits_per_week``**, or structured **``scheduled_sessions``** / **``pro_rata_scheduled_sessions``** / equivalent in ``schedule_config`` or ``billing_rules`` that drive **attended ÷ scheduled** (or per-session) math). **T** = those scheduled units in period from contract JSON.

**Does *not* qualify as ``C_VISIT_SESSION`` on slots alone:** ``schedule_config._type = prescribed`` with **only** ``slots`` listing **weekly time windows** (no ``visits_per_month``, no ``visits_per_week``, no period session count) **does not** trigger this class by itself — classify with the classifier table using the next matching rows (typically **``MAP-STAFF-CAL``** when the MAP-STAFF-CAL bullets all hold). **Do not** route those lines to **``C_RATE_OTHER``** Path 1 with **T = ``working_days``** solely because ``billing_rules`` use the ingest labels ``pro_rata_working_days`` / ``working_days`` — that label is **not** permission to skip **``MAP-STAFF-CAL``** for monthly OHC physician/MO seats.

**``C_AS_PER_ACTUALS``** — ``billing_model = as_per_actuals``. See AS_PER_ACTUALS section.

**Amount path (choose ONE per row from contract — absent-first logic; v2.16)**  
**Alignment:** For **``C_RATE_OTHER``**, this aligns with **PATH RULES** above. For classified rows, use the classifier spine first.

1) **Absent-deduction / fixed-period fee** (contract describes monthly/lump fee and **deducts or pro-rates for absence** against the scheduled commitment T):

2) **Paid-day accrual** (contract bills on **days actually paid** — present + paid leave — vs commitment T, **without** a separate absent-based deduction formula):

## Shift / 24x7 (**``C_SHIFT_MISS``**, ``deduction.method = per_shift_missed``)

**A — Shift schedule is definite in JSON**  
When you can derive **scheduled_shifts** (or equivalent units) for the billing period from ``schedule_config`` / ``billing_rules`` (non-empty shift list, explicit counts, or contract-fixed shifts in period), bill with the contract’s **per-shift** formula (e.g. ``rate_amount ÷ scheduled_shifts × missed_shifts``). **Missed shifts** must come from **shift/roster** evidence, not from guessing day blanks.

**Additional safeguards (v2.16 — definite shift schedules, 24x7):**
- Do **NOT** use per-person ``present_days`` alone as proxy for missed shifts unless shift-level roster evidence is explicitly present.
- If ``absent_days = 0`` and no explicit missed_shift count exists in payload, treat row as fully covered for deduction purposes (no per-shift deduction from day-level blanks/week-offs).
- Apply deduction only when missed shifts are explicitly evidenced (or when ``absent_days`` / missed units clearly represent scheduled shift misses).
- **Day-level proxy for this dataset:** if a scheduled day has any attendance marker indicating coverage (``Present*``, ``Locum Duty*``, paid leave if contract allows), treat that day's shift obligation as covered.
- Do **not** assume "missed shifts" solely because multiple shifts may exist in a day; **one covered marker** is sufficient proxy unless explicit shift roster evidence says otherwise.

**B — Shift schedule is *not* definite (common ingest gap)**  
If **scheduled_shifts** for the period **cannot** be computed from the payload (e.g. ``schedule_config.shifts`` is empty or has no period-bound count) **but** the line is still ``per_shift_missed``:
- Treat **``absent_days``** from ``attendance_records`` as **explicit day-level non-attendance** for that employee: **do not** bill the **full** monthly ``rate_amount`` when **absent_days > 0**.
- Apply the **calendar absence proxy** (same spine as ``MAP-STAFF-CAL``): **T = context ``calendar_days``**, compute **``prorated_base = rate_amount × max(0, T − absent_days) ÷ T``**, then add SC using the **same fixed-vs-percentage SC rules** as in ``MAP-STAFF-CAL`` DEFINITIONS. In ``calc_notes`` include **India calendar-day manpower override**, **``T=calendar_days (N)``**, tag **``C_SHIFT_MISS``**, and state **``per_shift_missed; shift roster incomplete — calendar absence proxy``** so reviewers see why shift units were not used.
- When **absent_days = 0**, full ``rate_amount`` is allowed under this proxy (no fabricated shift misses from blanks).

**C — Blanks vs marked absent**  
Do **not** treat **blank** day cells as ``absent_days`` (those are not in the payload). Only **``absent_days``** the server sends may trigger the proxy deduction in **B**.

Set ``validation.status=needs_human_review``.
- Do **not** use **rate_amount × contracted_quantity** as a blind default for every ``as_per_actuals`` line; use it **only** when **billing_rule_text** / **billing_rules** / **description** support that reading (e.g. stated cap, minimum, or monthly schedule rate for that line).

## Rule precedence (same line, conflicting fields)
1) ``billing_rules`` JSON 2) ``billing_rule_text`` 3) ``description`` 4) this prompt → else ``needs_human_review``.

**How precedence interacts with the calendar-T carve-out:**
- **Stack (1)–(4)** resolves **routing**, **which line class**, **caps**, **invoice admin rows**, **percentage-SC base**, and **whether fixed SC may prorate** (per DEFINITIONS: fixed SC co-prorates when **``billing_rules.deduction.applies_to``** includes **``service_charge``** or SC proration is explicit in **``billing_rule_text``** / **``deduction.formula``** — base-only “working days” phrasing alone does **not** override **``applies_to``**).
- **Frozen divisor:** For **``MAP-STAFF-CAL``** and **``C_SHIFT_MISS``** rows using the **calendar absence proxy**, the **T** in ``prorated_base = rate_amount × max(0,T−absent_days)÷T`` is **fixed** at Context **``calendar_days``**. Items (2) and (3) **cannot** replace that **T** with ``working_days`` or Mon–Fri counts, even if their wording says “working days in the month”.
- **Unaffected classes:** **``C_VISIT_SESSION``**, definite **per-shift** ``C_SHIFT_MISS``, **``C_RATE_OTHER``**, **``C_FIXED_MONTHLY``**, **``C_AS_PER_ACTUALS``** use **T** / units per their classifier rows and full precedence — no extra freeze beyond what that class already defines.

## Regression guards
- **generic / profile isolation:** Do **not** apply another profile’s annexure tier-mixing or global-admin conventions unless ``rate_lines`` explicitly encode them.
- **``C_VISIT_SESSION``:** when **``visits_per_month``** / **``visits_per_week``** (or equivalent **countable** session units) exist, keep visit/session math — **never** replace that row with ``MAP-STAFF-CAL``.
