### STEP 3B: FREQUENCY LOGIC

**Normalize scheduled units**

- **IF** `visits_per_month` exists: `scheduled_units = visits_per_month`.

- **ELSE IF** `visits_per_week` exists: `scheduled_units = visits_per_week × (calendar_days / 7)` (use Context **{calendar_days}**).

- **ELSE:** `scheduled_units = parsed_from_text` only when `billing_rules` / text give a definite number; else `validation.status = needs_human_review` and pick a single deterministic branch.

**Count actual units**

- `actual_units =` count of **Present** days per attendance rules (Locum Duty counts as present; Holiday / Week Off / Leave / null do not count as absent for deduction unless contract says otherwise).

**MODE SWITCH (CRITICAL RULE)**

- **IF** (`scheduled_units > 16` **OR** `expected_days >= 16`):  
  - **SWITCH TO CALENDAR MODE:** `T = calendar_days`, `A = absent_days`, `base = rate_amount × max(0, T − A) / T`.

- **ELSE:**  
  - **UNIT MODE:** `effective_units = min(actual_units, scheduled_units)` — **mathematical minimum** of those two scalars **only**. **Forbidden:** treating **`min`** as **subtraction** (`scheduled_units − actual_units`), or replacing **`min`** with **headcount** / **`contracted_quantity`** / “only one billed seat”.  
  - `base = rate_amount × (effective_units / scheduled_units)` (guard `scheduled_units > 0`). Use tools for **`min`** and **`div`** when enabled.

### STEP 3C: C_SHIFT_MISS (`per_shift_missed` — main-branch Shift / 24×7 rules)

**When:** `billing_model == "rate_attendance"` **and** `billing_rules.deduction.method == "per_shift_missed"`.

**Tag** in `calc_notes`: **`C_SHIFT_MISS`**.

**A — Shift schedule is definite in JSON**  
When **`scheduled_shifts`** (or equivalent billable shift units for the billing period) can be derived from **`schedule_config`** / **`billing_rules`** (non-empty **`shifts`**, explicit counts, or contract-fixed shift total for the period):

- **Do not** use **`present_days` alone** as a proxy for missed shifts unless **shift-level roster** evidence is explicitly present.

- **Day-level proxy:** if a scheduled day has **Present\***, **Locum Duty\***, or **contract-allowed paid leave**, treat that day’s shift obligation as **covered** unless roster evidence contradicts.
- **Do not** assume missed shifts **only** because **multiple shifts** might exist in a day; **one** coverage marker for that day is sufficient unless explicit shift roster says otherwise.

**B — Shift schedule is *not* definite** (common ingest gap: **`schedule_config.shifts`** empty **or** no period-bound shift count)

**C — Blanks vs marked absent**  
**Blank** attendance cells are **not** `absent_days`. Only server-supplied **`absent_days`** may drive deductions in **B**.

**Forbidden on proxy (B):** **`T = working_days`** as the proration divisor. **`billing_rule_text`** that says “working days” for manpower **does not** override **`T = calendar_days`** for this proxy. You may cite Mon–Fri count in `calc_notes` as **reference only**, not as **T** in the formula.

If SC proration is **not** explicit → **full** fixed SC.

- **ELSE** (`none` — typical TACO staffing ingest): **`SC = 0`**; do **not** embed **OHC** invoice **%** in each staffing row — keep **`OHC_ADMIN_INVOICE_PCT`** in **STEP 6** only.

### STEP 5: HEADCOUNT CAP (`contracted_quantity`)

Applies to **each** `contract_rate_line_id` that bills **employees** and has **`contracted_quantity`** = **N** (integer floor; if missing or invalid, **no cap** — bill every match).

- **Before this step:** every matched employee already has a row with **pre-cap** `final_amount` (**ROUTINE E** / HARD RULE **6**). **Do not** use the cap to avoid creating rows.  
- Let **M** = count of employee rows for this line (after routing).  
- **Rank** all **M** rows: **1)** `paid_days` desc **2)** pre-cap `final_amount` desc **3)** `employee_external_id` asc.  
- **Top min(N, M)** → **`is_omitted=false`**, keep **full** `final_amount` from the billing formula. **If M ≥ N, exactly N** rows must be non-omitted (**fill seats** — no under-billing).  
- **Remaining** → **`is_omitted=true`**, **`final_amount=0`**, **`omit_reason`** explains **contract headcount cap**.  
- **You MUST NOT** pre-omit a row that would land in the top **N** after this rank. If unsure, keep top **N** billed and set **`validation.status=needs_human_review`**.  
- **`totals.rows_included` / `rows_omitted`** (if schema includes them) must reflect this cap. Server may re-apply the same rank as a safety check.
