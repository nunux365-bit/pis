## §2.5 — Legacy parity checklist (v2.16 → still binding **via** §3 where duplicated)

Apply together with §3. **For all computation and classification, §3 alone is authoritative** — §2.5 is a **reviewer checklist**; it **never** overrides §3, even if phrasing differs. If §3 already states a rule, that rule wins; this list catches **nuance** reviewers relied on in v2.16:

1. **``attendance_required``:** For lines with ``attendance_required`` true, bill via real ``employee_external_id`` from attendance — **no** anonymous non-employee lump sums unless ``calc_notes`` cite an explicit contract exception.
2. **Contract-wide lines:** Emit per site when in ``rate_lines``; in ``calc_notes`` note **contract-wide**; finance must **not** double-count the same ``contract_rate_line_id`` across plants in consolidated totals.
3. **Headcount cap:** Output **all** matched employees; only top **N** billed; **never** pre-omit someone who ranks in top **N**; ``totals.rows_included`` / ``rows_omitted`` must reflect capping.
4. **Attendance fields:** ``expected_days`` is **given** — **do not** recompute from Excel header totals. **Default leave is paid** unless contract marks LOP; use ``paid_days`` for accrual paths unless unpaid leave applies.
5. **Session / visit lines:** For true session contracts, deduct **missed sessions**; if attended ≥ scheduled sessions and no session absence, **full monthly** before separate penalties; do **not** force calendar 28/30/31 denominator unless contract or MAP-STAFF-CAL rules say so.
6. **Shift / ``per_shift_missed`` (when shift roster is definite):** Do **not** use ``present_days`` alone as missed-shift proxy without roster evidence; **one** day-level coverage marker (``Present*``, ``Locum*``, contract-allowed paid leave) can satisfy that day's shift obligation unless roster proves otherwise; do **not** infer missed shifts only because multiple shifts/day exist.
7. **Math self-checks:** Include ``math_professor_row_math`` (or **row_math_ok**), **no_double_absent_subtraction** on paid-day paths, **unit_consistency** / **unit_consistency_check**, **admin_pct_ok** when OHC admin applies, **totals_reconciled**.
8. **``as_per_actuals``:** Read like **lawyer + accountant** — minimum, cap, "lower of", "if not provided", **actuals_markup_pct** only with a **cost base** in payload; do not blind ``rate_amount × contracted_quantity``.
9. **generic commercial:** Staffing ``rate_attendance`` rows with ``service_charge_type=none`` are **base-only**; **OHC_ADMIN_INVOICE_PCT** is **once** per line id — **staffing base for admin** is defined in the **profile-specific** §3 block (sum rules) — do **not** embed global % in each staffing row.

**Calendar-T carve-out (overrides legacy wording):** For **``MAP-STAFF-CAL``** and **``C_SHIFT_MISS``** with **calendar absence proxy**, **T** is **always** Context ``calendar_days`` — legacy prose that implied ``working_days`` as divisor for those fingerprints does **not** apply.

**Profile-specific rules (``billing_profile=generic`` — generic / CWP MSA annexure style):**
- **Staffing base vs invoice admin:** On ``rate_attendance`` lines, **ingest usually forces** ``service_charge_type=none`` — staffing ``final_amount`` is **base only**. **All** contract **percentage** administration for the period is almost always a single ``fixed_monthly`` line ``OHC_ADMIN_INVOICE_PCT`` with ``billing_rules.invoice_admin_pct`` (often 10). Do **not** fold that % into each staffing row.
- **``OHC_ADMIN_INVOICE_PCT`` row:** Exactly one summary row per that ``contract_rate_line_id``; ``employee_external_id`` and ``employee_name`` null. **Staffing base (``sum_B``):** sum of **post-rounding** ``final_amount`` values (the exact numbers in ``summary_rows[].final_amount``) for **non-omitted** rows that are **employee staffing billed as** ``billing_model = rate_attendance`` for this site/period — **exclude** the ``OHC_ADMIN_INVOICE_PCT`` row itself, **exclude** ``fixed_monthly``, **exclude** ``as_per_actuals``, and **exclude** any other non–``rate_attendance`` billing models. ``final_amount`` = round(**sum_B** × ``invoice_admin_pct`` / 100, 0.01). Document **sum_B**, **pct**, and formula in ``calc_notes``.

Do **not** use context ``working_days`` as **T** for ``MAP-STAFF-CAL``.
- **``C_SHIFT_MISS`` / nurses (generic):** When ``per_shift_missed`` applies but ``schedule_config`` does not give a period shift count (empty ``shifts``), use the shared **calendar absence proxy** — **absent_days > 0** must reduce ``final_amount``; do not default to full monthly fee for that employee.

### generic — Working-day absence vs visits (``rate_attendance`` only; classifier order matters)
Apply **after** you know the line class from the shared classifier (``C_VISIT_SESSION``, ``C_SHIFT_MISS``, ``MAP-STAFF-CAL``, etc.):

1. Read ``billing_rules`` for that ``rate_line`` first. If it defines **visits / sessions / per_visit / scheduled_sessions / per_shift_missed** billing units, bill using **those** units — do **not** replace them with the **working-days** formula in step (3).
2. **Carve-out — calendar-T classes:** If the line is **``MAP-STAFF-CAL``** or **``C_SHIFT_MISS``** billed with the **calendar absence proxy**, **skip** step (3) — use shared DEFINITIONS (**``calendar_days``** as **T**, not Context ``working_days``). **Also skip (3)** if the line is **``C_RATE_OTHER``** and **India manpower override** applies (§ **T, target_present_days** — calendar **T** for ≥5 days/week monthly manpower): use **``calendar_days``** as **T** and **``rate_amount × max(0, T − absent_days) ÷ T``** per that section — **do not** apply the working-days formula in (3).
3. **Remaining ``rate_attendance`` (e.g. some ``C_RATE_OTHER``):** Else if ``billing_rules.pro_rata.method == working_days`` **and** ``billing_rules.deduction.method == pro_rata_working_days``, then this step is the **generic implementation of ``C_RATE_OTHER`` Path 1** with **T = Context ``working_days``**: ``final_amount = rate_amount × max(0, working_days − absent_days) ÷ working_days`` (guard prevents negative amounts when ``absent_days > working_days``). 4. For rows covered by (3) only: do **not** use ``rate_amount × present_days ÷ working_days`` or ``× paid_days ÷ working_days``. Wording in ``billing_rule_text`` (e.g. “twice a week”) does **not** override (3) unless (1) applies.
5. If ``billing_rule_text`` and structured ``billing_rules`` still conflict, set ``needs_human_review`` and explain — do **not** invent a hybrid formula.

## MATH-PRIMARY discipline (``final_amount`` vs ``calc_notes``)
- **``final_amount`` is canonical after computation:** Compute each row’s amount **once** with explicit arithmetic (base → per-contract SC/add-ons → **one** currency round to 2 decimals at the end if applicable). It is **not** derived from prose in ``calc_notes``.
- **``calc_notes`` is documentation only:** After the number is fixed, write a **transcript** of the **same** steps. The string must contain **exactly one** closing total that **equals** ``final_amount`` — never a second “= …” with a different value, never “override / policy / corrected” alternate totals. **Forbidden:** any trailing line such as **``Hard-closing-total reconciliation applied per gate 11 = …``**, **``PRE-OUTPUT item 11``**, or **``reconciliation``** + a **new** figure after **``total = …``** — that is a **dual spine**; internal gates are **silent** (see item 11).
- **Notes anchor rule:** If ``calc_notes`` ≠ ``final_amount``, **default: rewrite ``calc_notes``** to match ``final_amount``. **Only** if ``final_amount`` is a clear **typo** against contract rules for that row, correct ``final_amount`` **once** by re-applying the **identical** formula — **never** “fix” by inventing a different method (e.g. switching **T**, SC path, or gross-up). If a numeric mismatch **still** exists at emit, **PRE-OUTPUT item 11** applies.
- **No dual spine:** **``MAP-STAFF-CAL``** and **calendar-proxy ``C_SHIFT_MISS``** use **T = Context ``calendar_days``** only — **never** a second divisor (e.g. ``working_days`` as **T**) or second billed total for the same row. **One** SC evaluation per DEFINITIONS (full vs prorated fixed SC); **do not** re-apply ``billing_rules`` / “proportional deduction on service charge” / audit prose **after** the transcript’s closing total. **math_professor_row_math** must use the **same** class + **T** + SC path as computation — **not** a fresh **T** from ingest “for audit.”
- **Forbidden shortcuts:** Gross-ups such as ``÷0.98``, ``×1.02``, or similar **unless** ``billing_rules`` / ``billing_rule_text`` / ``description`` **explicitly** prescribes that formula.

## DEFINITIONS (use these names consistently in ``calc_notes`` class field)
**``MAP-STAFF-CAL`` — Monthly / high-frequency human staffing (calendar **T** only)**  
Matches **employee** lines that are **monthly** (or period lump) **human** staffing with absence proration and **no** low-frequency visit pattern — typical OHC doctor/nurse/paramedic seats.

A ``summary_rows`` line is classified as **``MAP-STAFF-CAL``** when **all** hold for its ``contract_rate_line_id``:
- ``billing_model`` = ``rate_attendance``
- ``billing_rules.pro_rata.method`` = ``working_days`` *(ingest label for LOP style — **not** permission to use Context ``working_days`` as **T**)*
- ``billing_rules.deduction.method`` = ``pro_rata_working_days``
- ``schedule_config`` has **no** ``visits_per_month`` and **no** ``visits_per_week`` (null/absent/empty). **``prescribed``** ``schedule_config`` with only **weekly ``slots``** (time-of-day bands on ``day_of_week``) **without** those visit counters **satisfies** this bullet — treat slots as **duty/coverage metadata** for a **monthly seat**, not as countable visit units unless **``C_VISIT_SESSION``** is triggered per its definition below.
- ``deduction.method`` is **not** ``per_shift_missed``
- The line is **not** already classified as **``C_VISIT_SESSION``** (visit/session billing — see **narrow** definition below)

**Denominator T (product; same for tcs / taco / generic):** **T = context ``calendar_days``** (N from Context). **Never** Context ``working_days`` for this class.

**Why calendar:** Human staffing billed **monthly** or at **≥5 days/week** (Mon–Fri-style) uses **calendar-month** proration so weekend-inclusive months match India MIS policy. Wording in ``billing_rule_text`` (e.g. “deduct by working days in the month”) is **commercial language**; it **must not** replace **T** with ``working_days``.

**Prorated base:** ``prorated_base = rate_amount × max(0, T − absent_days) ÷ T`` (``absent_days`` from ``attendance_records``).

**Service charge on the same row (apply after ``prorated_base`` is fixed):**
- **``service_charge_type = percentage``:** SC = ``prorated_base × (service_charge_value ÷ 100)`` unless ``billing_rule_text`` / ``billing_rules`` explicitly define a different base for the percentage.
- **``service_charge_type = fixed`` (default):** **SC = ``service_charge_value``** in full — **no** absence factor, **no** ``× (T − absent_days) ÷ T``, **no** inferring proration from base-fee wording alone.
- **``service_charge_type = fixed`` (proration — narrow exception):** Multiply fixed SC by an absence or partial-month factor **only** when ``billing_rules`` / ``billing_rule_text`` / ``description`` **explicitly** ties the **service charge** (or unambiguous “SC” / “service charge” label) to **pro-rata**, **proportional deduction**, or **same ratio as** base/attendance/LOP. **Phrases that only describe the base fee** (e.g. “deduct absent days”, “working days in the month” for manpower) **do not** prorate fixed SC. If SC proration is **not** explicit → **full** fixed SC.

**Row total:** ``final_amount = prorated_base + SC`` (plus any other add-ons the same contract fields explicitly require), then round **once** for currency if needed.

**``calc_notes`` for ``MAP-STAFF-CAL``:** Must include the literal substring **India calendar-day manpower override** (downstream review uses it) and **``T=calendar_days (N)``** with **N** = Context value.

**Forbidden on ``MAP-STAFF-CAL``:** ``rate_amount × paid_days ÷ T``, ``rate_amount × present_days ÷ T``, or mixing paid-day accrual with absent-proration on the **same** row.

**``C_VISIT_SESSION``** — Visit or scheduled-session billing where JSON defines **countable billable units in the billing period** (e.g. **non-null ``visits_per_month``**, **``visits_per_week``**, or structured **``scheduled_sessions``** / **``pro_rata_scheduled_sessions``** / equivalent in ``schedule_config`` or ``billing_rules`` that drive **attended ÷ scheduled** (or per-session) math). **T** = those scheduled units in period from contract JSON.

**Does *not* qualify as ``C_VISIT_SESSION`` on slots alone:** ``schedule_config._type = prescribed`` with **only** ``slots`` listing **weekly time windows** (no ``visits_per_month``, no ``visits_per_week``, no period session count) **does not** trigger this class by itself — classify with the classifier table using the next matching rows (typically **``MAP-STAFF-CAL``** when the MAP-STAFF-CAL bullets all hold). **Do not** route those lines to **``C_RATE_OTHER``** Path 1 with **T = ``working_days``** solely because ``billing_rules`` use the ingest labels ``pro_rata_working_days`` / ``working_days`` — that label is **not** permission to skip **``MAP-STAFF-CAL``** for monthly OHC physician/MO seats.

**FMO with ``visits_per_month`` set** (e.g. 4) **remains** ``C_VISIT_SESSION`` — the numeric visit counter **does** trigger this class.

**``C_SHIFT_MISS``** — ``deduction.method = per_shift_missed``. Prefer **shift-unit** **T** and **missed_shifts** from ``schedule_config`` / roster when the JSON supports a **definite** scheduled shift count for the billing period. If that count **cannot** be determined (e.g. empty ``shifts`` array, no period shift total), use the **calendar absence proxy** in the Shift section — **do not** bill full ``rate_amount`` when ``absent_days > 0`` in that situation.

**``C_FIXED_MONTHLY``** — ``billing_model = fixed_monthly``. Prorate per ``billing_rules`` (e.g. ``calendar_days`` partial month).

**``C_AS_PER_ACTUALS``** — ``billing_model = as_per_actuals``. See AS_PER_ACTUALS section.

**``C_RATE_OTHER``** — Any remaining ``rate_attendance`` not in the classes above; choose Path 1 vs Path 2 below.

| **C_SHIFT_MISS** | ``per_shift_missed`` | Shift count from ``schedule_config`` when definite; else **calendar_days** proxy | Shift section: strict shift math **or** absence proxy |
| **C_FIXED_MONTHLY** | ``fixed_monthly`` | Per ``billing_rules`` | Flat or calendar partial |
| **C_AS_PER_ACTUALS** | ``as_per_actuals`` | N/A | Caps / minimums / fallback / 0 |
| **MAP-STAFF-CAL** | All bullets in DEFINITIONS | **``calendar_days``** from Context | ``prorated_base`` + SC per DEFINITIONS |
| **C_RATE_OTHER** | Other ``rate_attendance`` | Per contract | Path 1 or Path 2 |

## PATH RULES (``C_RATE_OTHER`` only)
- **Path 1 — Absent-deduction:** ``final_amount`` ∝ ``max(0,T−A)/T`` × rate (+ SC). Do **not** also multiply by ``P/T``.
- **Path 2 — Paid-day accrual:** uses **paid_days** vs **T** only when contract bills on paid presence **without** Path 1. Never subtract **A** again.
- Ambiguous → ``needs_human_review``.

## T, target_present_days, and unit policy (v2.16 — classifier overrides first)
**Classifier overrides (read first):** If the row is **``MAP-STAFF-CAL``**, **``C_SHIFT_MISS``** (calendar absence proxy), **``C_VISIT_SESSION``**, **``C_FIXED_MONTHLY``**, or **``C_AS_PER_ACTUALS``**, determine **T** and the amount spine from **DEFINITIONS**, **Shift**, **classifier table**, and dedicated sections **first**. The bullets below apply to **remaining** rows (e.g. **``C_RATE_OTHER``**) and to **nuance** where the classifier leaves **T** underspecified — they must **not** contradict **MAP-STAFF-CAL** / calendar-proxy **``C_SHIFT_MISS``** / visit-session math.

Define for each employee staffing row where relevant (state T, A, P in ``calc_notes``):
- **T** = **target_present_days** for the period: contractual scheduled/billable day count.
  - Prefer explicit contract numbers (``billing_rule_text``, ``billing_rules``, ``schedule_config``, ``minimum_units_per_period``, ``description``).
  - **"5 days a week" / Mon–Fri:** use context **``working_days``** (Mon–Fri count in billing period) as T when no conflicting explicit count **and** the row is **not** **``MAP-STAFF-CAL``** / calendar-proxy **``C_SHIFT_MISS``** (those use **``calendar_days``** per DEFINITIONS).
  - Else fall back to attendance **``expected_days``** for that employee.
- **A** = attendance **``absent_days``** (source row).
- **P** = **``paid_days``** from attendance (or ``present_days`` only if leave unpaid by contract).

T derivation and unit policy (MUST follow where classifier does not already fix T):
Policy precedence for denominator selection (highest to lowest):
1) India manpower override (defined below) when applicable — **when the **``MAP-STAFF-CAL``** fingerprint applies, DEFINITIONS are operative** (calendar **T**, mandatory **India calendar-day manpower override** phrasing).
2) Explicit ``billing_rules`` method.
3) Explicit schedule semantics from ``schedule_config``.
4) Attendance fallback (``expected_days``) only when above are unavailable.

India manpower override (business policy; highest priority when applicable):
- Applies only to employee-based monthly manpower lines (not non-employee, not pure per_visit billing).
- If schedule implies **5 or more days per week** (from ``schedule_config.days_per_week``, clear ``billing_rule_text``, or ``description``),
  use **calendar days in billing period** as denominator T (same as Context **``calendar_days``**).
- This override supersedes ``scheduled_sessions`` interpretation for such high-frequency monthly manpower lines.
- Exception: low-frequency visit contracts (typically <5 visits/week) and explicit per-visit constructs remain session-based.
- When override is applied, write in ``calc_notes``: "India calendar-day manpower override applied" (and **``T=calendar_days (N)``** when using **``MAP-STAFF-CAL``** per DEFINITIONS).

Method-specific denominator when override is not applicable **and** classifier does not fix T:
- If ``billing_rules.pro_rata.method == calendar_days``: T = Context **``calendar_days``**.
- If ``billing_rules.pro_rata.method == working_days`` OR ``billing_rules.deduction.method == pro_rata_working_days``: **for rows that match **``MAP-STAFF-CAL``**, T = Context **``calendar_days``** (DEFINITIONS). For **other** rows (e.g. some **``C_RATE_OTHER``**), T = Context **``working_days``** when that spine applies.
- If ``billing_rules.deduction.method == pro_rata_scheduled_sessions`` OR ``billing_rules.pro_rata.method == scheduled_sessions``:
  - Treat line as session/scheduled-unit based.
  - Derive T as scheduled sessions/units in period from ``schedule_config`` (e.g. ``visits_per_week``, prescribed slots).
  - Use attended sessions (or closest attendance proxy) as numerator.
  - Non-scheduled blank days must not reduce billing.
- If ``billing_rules.deduction.method == per_shift_missed``: T = scheduled shifts/coverage units from ``schedule_config`` when computable; otherwise use **Shift** section **B** (calendar absence proxy) — do not apply the generic ``working_days`` T bullet to proxy rows.
- Never mix session numerator with day denominator (or vice versa). If unit alignment is unclear, set ``validation.status=needs_human_review``.

**Amount path (choose ONE per row from contract — absent-first logic; v2.16)**  
**Alignment:** For **``C_RATE_OTHER``**, this aligns with **PATH RULES** above. For classified rows, use the classifier spine first.

1) **Absent-deduction / fixed-period fee** (contract describes monthly/lump fee and **deducts or pro-rates for absence** against the scheduled commitment T):
   - **Billable units** = max(0, T - A). Do not also apply a P/T pro-rate in a way that subtracts absent twice. If leave is paid and counted inside the commitment, explain in ``calc_notes`` how leave interacts with T (leave is not absent).
   - Fixed fee for period: **final_amount = rate_amount × max(0, T - A) / T** when T > 0.
   - Per-day rate: align with contract; if rate is per billable day after absent deduction, **final_amount = rate_amount × max(0, T - A)** only if contract matches that reading.
   - For shift-based ``per_shift_missed`` lines, only convert to ``rate_amount × covered_units / scheduled_units`` when covered/missed units are explicitly known from shift evidence.

2) **Paid-day accrual** (contract bills on **days actually paid** — present + paid leave — vs commitment T, **without** a separate absent-based deduction formula):
   - **final_amount = rate_amount × P / T** (fixed period pro-rate) or **rate_amount × P** (per-day) per rate_unit + contract.
   - Here absent is already excluded from P via ``present_days``; **do not subtract A again.**

If unsure which path applies, use path (1) when ``billing_rule_text`` emphasizes absence/LOP/deduction; else path (2). Set ``validation.status=needs_human_review`` and document T, A, P, path, and formula.
If A=0 but ``final_amount`` is below baseline, ``calc_notes`` must explicitly state the non-absent reduction driver (e.g. period-scoped ``paid_days`` < T due to blank/unpaid-leave/non-billable day status).

Session-based physician/specialist safeguard:
- For monthly physician/specialist lines with scheduled sessions (e.g. "2 hours, twice a week"), base deduction on **missed scheduled sessions only**.
- If attended_sessions >= scheduled_sessions_in_period and absence on scheduled sessions is 0, bill full monthly rate (before any separate contractual penalties explicitly provided).
- Do not apply denominator 28/30/31 calendar days to such session-based lines unless contract explicitly says calendar-days proration OR India manpower override / **``MAP-STAFF-CAL``** applies per DEFINITIONS.

## Attendance symbols & Context fields
- **A** = ``absent_days``; **P** = ``paid_days`` (present + leave unless contract marks leave unpaid).
- Context **``working_days``** = Mon–Fri count in the billing period (payload field).
- **``MAP-STAFF-CAL``** and **``C_SHIFT_MISS``** billed with the **calendar absence proxy:** **T** = Context **``calendar_days``** only. **Do not** set **T** = ``working_days`` on these rows; **do not** cite “working days” in ``billing_rule_text`` as authority to swap the divisor. ``working_days`` may still appear in ``calc_notes`` as **reference** (e.g. “Mon–Fri count = …”) but **not** as **T** in the proration formula.
- **Other classes** (e.g. **``C_RATE_OTHER``**, non-proxy shift math): **T** may be ``working_days`` or another contract-defined denominator **only** when the classifier + **``billing_rules``** / unambiguous contract text agree — not by overriding **``MAP-STAFF-CAL``** / proxy rules.
- **expected_days** = roll span minus week-off cells — **T** fallback only if classifier leaves **T** undefined.

## Shift / 24x7 (**``C_SHIFT_MISS``**, ``deduction.method = per_shift_missed``)

**A — Shift schedule is definite in JSON**  
When you can derive **scheduled_shifts** (or equivalent units) for the billing period from ``schedule_config`` / ``billing_rules`` (non-empty shift list, explicit counts, or contract-fixed shifts in period), bill with the contract’s **per-shift** formula (e.g. ``rate_amount ÷ scheduled_shifts × missed_shifts``). **Missed shifts** must come from **shift/roster** evidence, not from guessing day blanks.

**Additional safeguards (v2.16 — definite shift schedules, 24x7):**
- Do **NOT** use per-person ``present_days`` alone as proxy for missed shifts unless shift-level roster evidence is explicitly present.
- If ``absent_days = 0`` and no explicit missed_shift count exists in payload, treat row as fully covered for deduction purposes (no per-shift deduction from day-level blanks/week-offs).
- Apply deduction only when missed shifts are explicitly evidenced (or when ``absent_days`` / missed units clearly represent scheduled shift misses).
- **Day-level proxy for this dataset:** if a scheduled day has any attendance marker indicating coverage (``Present*``, ``Locum Duty*``, paid leave if contract allows), treat that day's shift obligation as covered.
- Do **not** assume "missed shifts" solely because multiple shifts may exist in a day; **one covered marker** is sufficient proxy unless explicit shift roster evidence says otherwise.

**B — Shift schedule is *not* definite (common ingest gap)**  
If **scheduled_shifts** for the period **cannot** be computed from the payload (e.g. ``schedule_config.shifts`` is empty or has no period-bound count) **but** the line is still ``per_shift_missed``:
- Treat **``absent_days``** from ``attendance_records`` as **explicit day-level non-attendance** for that employee: **do not** bill the **full** monthly ``rate_amount`` when **absent_days > 0**.
- Apply the **calendar absence proxy** (same spine as ``MAP-STAFF-CAL``): **T = context ``calendar_days``**, compute **``prorated_base = rate_amount × max(0, T − absent_days) ÷ T``**, then add SC using the **same fixed-vs-percentage SC rules** as in ``MAP-STAFF-CAL`` DEFINITIONS. In ``calc_notes`` include **India calendar-day manpower override**, **``T=calendar_days (N)``**, tag **``C_SHIFT_MISS``**, and state **``per_shift_missed; shift roster incomplete — calendar absence proxy``** so reviewers see why shift units were not used.
- When **absent_days = 0**, full ``rate_amount`` is allowed under this proxy (no fabricated shift misses from blanks).

**C — Blanks vs marked absent**  
Do **not** treat **blank** day cells as ``absent_days`` (those are not in the payload). Only **``absent_days``** the server sends may trigger the proxy deduction in **B**.

## AS_PER_ACTUALS (**``C_AS_PER_ACTUALS``** — v2.16 + current)
- **Always emit a summary row** for the rate line when it exists in ``rate_lines`` (do not silently drop the line).
- Set **contracted_rate** to the contractual reference: usually **rate_amount** (cap, schedule rate, or list rate); **contracted_count** from **contracted_quantity** (default 1 if absent).
- **Deterministic pattern gate (generic — apply before pure judgment):** Scan **``billing_rule_text``**, **``description``**, and structured **``billing_rules``** in order:
  - If any of **minimum**, **fixed monthly**, **monthly charge**, **if actuals not provided**, **in absence of bills**, **deemed**, **default to**, **schedule rate**, **at least** (monetary floor) → prefer **``final_amount`` = rate_amount × contracted_quantity** (or the stated minimum) when that reading is contractually coherent; cite the phrase in **calc_notes**.
  - Else if **as per actual**, **reimbursement**, **at cost**, **variable** appear **and** the prior bullet’s fallback words **do not** appear → **``final_amount`` = 0** with **``needs_human_review``** unless a numeric fallback is explicit in JSON.
  - Else if **cap**, **not exceeding** (ceiling), **upper limit**, **lower of** → use **rate_amount** (or stated cap) as **ceiling**; if actuals missing and contract says bill cap → **``final_amount``** to that cap with explanation; **``needs_human_review``** if ambiguous.
  - Else → **``needs_human_review``**; default **``final_amount`` = 0** only if **no** fallback/cap/minimum language exists.
- **Read the contract like a lawyer + accountant** for cases **outside** the pattern gate or when patterns conflict. Use **description**, **billing_rule_text**, and **billing_rules** together. Look for language such as: *minimum*, *monthly*, *if actuals not provided*, *in absence of bills*, *deemed*, *not exceeding*, *lower of actual or cap*, *reimbursement capped at*, *fixed charge until*, *default to*, *schedule rate*.
- **When actuals are not in this run but the contract specifies what to bill anyway**, you MUST use that rule:
  - If the contract sets a **fixed/minimum monthly or per-period charge** when proof is missing → **final_amount** = that amount (often equals **rate_amount × contracted_quantity** when the line is written as a flat fee).
  - If the contract says **bill the lower of actual cost or cap** and actuals are missing → treat **cap** (**rate_amount** basis) as the **billable ceiling**; if the only defensible reading is "charge cap when actuals unknown", set **final_amount** to that cap and explain in **calc_notes** (set ``validation.status=needs_human_review`` if ambiguous).
  - If **billing_rules** (or prose) gives a numeric **fallback when actuals are absent**, use it for **final_amount** and cite the field or quote in **calc_notes**.
  - Apply **actuals_markup_pct** only when you are inferring an amount from a stated cost base; if there is no cost base in the payload, rely on contract fallback/cap language, not markup alone.
- **Only when** the contract truly bills **pure variable cost** with **no** minimum, cap-as-default, or "if not provided" amount, set **final_amount = 0**, **is_omitted = false**, and **calc_notes** = why actual proof is required and nothing else applies. Set ``validation.status=needs_human_review``.
- Do **not** use **rate_amount × contracted_quantity** as a blind default for every ``as_per_actuals`` line; use it **only** when **billing_rule_text** / **billing_rules** / **description** support that reading (e.g. stated cap, minimum, or monthly schedule rate for that line).
- ``actuals_available=false`` does not imply 0 — always read contract fields before choosing zero.

## Computation workflow (single evaluation — silent; do not print steps)
1. **Profile / routing:** Apply the **profile-specific** block; map each employee to the correct ``contract_rate_line_id``; enforce FMO/MO routing; **generic:** staffing stays base-only where ``service_charge_type=none``; **OHC_ADMIN_INVOICE_PCT** once from staffing subtotal × pct (``sum_B`` per profile rules).
2. **Classification:** Exactly **one** line class per billable row (**classifier table**). **``C_VISIT_SESSION``** only when **countable** visit/session units exist (see DEFINITION) — **``prescribed.slots`` without visit counters does not count.** **``MAP-STAFF-CAL``** must not apply if **``C_VISIT_SESSION``** or **``C_SHIFT_MISS``** applies.
3. **Amounts + notes:** For each billable row, compute **numeric** ``final_amount`` **once** (class + rate line + contract; base → SC → one round). Write ``calc_notes`` as the **transcript** only. **``MAP-STAFF-CAL``:** **T = ``calendar_days``**; **India calendar-day manpower override** in ``calc_notes``. **``C_SHIFT_MISS``:** **per-shift** math when shift count is **definite** in JSON; else **calendar absence proxy** — **never** full ``rate_amount`` when **absent_days > 0** if shift **T** was not computable.
4. **Totals:** ``totals.final_amount_total`` = **exact** sum of non-omitted ``final_amount`` (same rounding as rows). Reconcile **``OHC_ADMIN_INVOICE_PCT``** vs staffing subtotal per profile. If ``calc_notes`` do not close to ``final_amount``, **rewrite ``calc_notes``** — do **not** change ``final_amount`` to match a mistaken narrative unless it is a clear arithmetic typo under the **same** formula.
5. **Checks:** Apply **Math Validator checks** (``validation.self_checks``); enforce headcount cap (**STRICT RULES**); non-negative fields; ``totals.rows_included + totals.rows_omitted = len(summary_rows)``; unresolved ambiguities → ``validation.validation_errors``.

## PRE-OUTPUT GATE (all true before emitting JSON)
1. **Computation workflow** and **Math Validator** complete; all items below satisfied.
2. No invented ids; employee ids ⊆ ``attendance_records``.
3. **``MAP-STAFF-CAL``** rows, and **``C_SHIFT_MISS``** rows billed with the **calendar absence proxy** (shift roster incomplete): ``calc_notes`` contains **India calendar-day manpower override** and ``T=calendar_days (…)``.
4. Every non-omitted row: **one** billing spine only — computed ``final_amount`` matches the **single** closing total in ``calc_notes`` (no “audit adjustment” that changes method). **No** alternate totals, **no** “policy override” numbers. **``MAP-STAFF-CAL``** / calendar-proxy **``C_SHIFT_MISS``:** **T** is **always** ``calendar_days`` — **do not** override **T** with ``working_days`` using ``billing_rule_text``; **``service_charge_type=fixed``** → **full** ``service_charge_value`` unless DEFINITIONS’ explicit SC-proration exception. Other classes: label/routing exceptions per **``billing_rules``** / **``billing_rule_text``** / **``description``** when unambiguous (physician rows: **FMO/MO** routing rules above).
5. Schema keys and value types only as in the schema example.
6. No negative ``contracted_rate`` / ``contracted_count`` / ``present_days`` / ``absent_days`` / ``final_amount``.
7. ``totals.final_amount_total`` equals sum(``final_amount`` where ``is_omitted=false``) within 0.01.
8. ``totals.rows_included`` + ``totals.rows_omitted`` == len(``summary_rows``).
9. Non-employee rows: ``employee_external_id`` and ``employee_name`` null.
10. For each employee-based ``contract_rate_line_id``, billed rows (``is_omitted=false``) count must be <= ``contracted_quantity`` (default 1).
11. **Hard closing-total reconciliation (run last — silent; never narrate in ``calc_notes``):** For each row with ``is_omitted=false``, let **terminal** = the numeric amount on the **billing arithmetic** closing line (the **``total = …``** / final ``= …`` from **prorated_base + SC** / row formula — **not** any appended “gate 11”, “reconciliation”, “PRE-OUTPUT”, or “hard closing” line). **First:** if ``calc_notes`` contain such an appended line with a **different** number, **delete** it entirely — it is **invalid** output. **Then:** if **terminal** parses unambiguously and **|terminal − final_amount| > 0.01**, **set ``final_amount`` = terminal** (2 decimals), **set ``validation.status`` = ``needs_human_review``**, record the mismatch in ``validation.validation_errors`` (and **self_checks** / **note_field_mismatch_reconciled**) **without** writing that explanation into ``calc_notes``, and **recompute** ``totals.final_amount_total`` (and **``OHC_ADMIN_INVOICE_PCT``** if present). **Do not** add **``calc_notes``** prose about item 11 or reconciliation amounts. If **terminal** cannot be parsed, **rewrite ``calc_notes``** to one clean transcript per **Notes anchor rule** or flag ``needs_human_review`` — **never** emit JSON with **both** a clear arithmetic **``total =``** and a conflicting ``final_amount``.

## Calendar proration outside ``MAP-STAFF-CAL``
If ``billing_rules.pro_rata.method=calendar_days`` on a line that is **not** ``MAP-STAFF-CAL``, use Context ``calendar_days`` as **T** and document **India calendar-day manpower override** when it is employee monthly staffing.

## Rule precedence (same line, conflicting fields)
1) ``billing_rules`` JSON 2) ``billing_rule_text`` 3) ``description`` 4) this prompt → else ``needs_human_review``.

**How precedence interacts with the calendar-T carve-out:**
- **Stack (1)–(4)** resolves **routing**, **which line class**, **caps**, **invoice admin rows**, **percentage-SC base**, and **whether fixed SC may prorate** (per DEFINITIONS: fixed SC prorates **only** on **explicit** SC-level text — base-only “working days” does **not** count).
- **Frozen divisor:** For **``MAP-STAFF-CAL``** and **``C_SHIFT_MISS``** rows using the **calendar absence proxy**, the **T** in ``prorated_base = rate_amount × max(0,T−absent_days)÷T`` is **fixed** at Context **``calendar_days``**. Items (2) and (3) **cannot** replace that **T** with ``working_days`` or Mon–Fri counts, even if their wording says “working days in the month”.
- **Unaffected classes:** **``C_VISIT_SESSION``**, definite **per-shift** ``C_SHIFT_MISS``, **``C_RATE_OTHER``**, **``C_FIXED_MONTHLY``**, **``C_AS_PER_ACTUALS``** use **T** / units per their classifier rows and full precedence — no extra freeze beyond what that class already defines.

## Regression guards
- **Site-scoped annexures:** do not apply one site’s annexure rate to another site’s attendance when the contract scopes lines per plant (this run is **generic**, not **tcs** — do **not** import TCS tier grids unless they appear in ``rate_lines``).
- **``C_VISIT_SESSION``:** when **``visits_per_month``** / **``visits_per_week``** (or equivalent **countable** session units) exist, keep visit/session math — **never** replace that row with ``MAP-STAFF-CAL``.
- **MO / physician with only ``prescribed.slots``** (no visit counters) **+** full **MAP-STAFF-CAL** fingerprint: **calendar-days** ``MAP-STAFF-CAL``, **not** ``C_RATE_OTHER`` with **T = working_days**.

- **as_per_actuals / BMW:** amounts from contract text only.
